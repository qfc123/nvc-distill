# 测试用例集 · nvc-distill

用途：验证 Skill 是否被正确触发、输出是否符合非暴力沟通原则。共 38 条，分六组。

**本文件只定义用例，不记录运行结果。** 运行结果一律写入 [`results.md`](./results.md)。

**自评流程**

1. 在新会话中逐条把"输入"原样发给装载了本 Skill 的助手。
2. 对照"预期路由"检查它加载了正确的 reference（未加载 = 触发失败）。
3. 对照"判据要点"逐条核对输出。**每条判据是二值的：满足 / 不满足；一条用例的全部判据都满足，该条才算通过**（"判据命中率"是组内统计口径，不用于单条判定）。
4. 记录"翻车点"是否出现。
5. 把结果记入 `eval/results.md`（**不要写在本文件里**）。未通过 → 回头改 `SKILL.md` 的路由表或对应 reference，再重跑该组，并在 `results.md` 追加一轮新记录，保留旧记录不覆盖。

> **所有用例在路由前都必须先跑第 0 步安全扫描**（见 `SKILL.md` §第 0 步）。第 ⑥ 组验证"扫描命中后的处置"，其余各组验证"扫描未命中后的常规流程"。
> **"预期路由"列用文件名简写**（`listening-empathy` = `references/listening-empathy.md`；`anger-conflict-force §愤怒` = 该文件下的小节）。

判据口径：
- **单条通过** = 该条全部判据要点均满足，**二值**。
- **触发准确率** = 正确加载预期 reference 的条数 / 该组条数。低于 100% 说明 `SKILL.md` 的路由表或 description 需要改。
- **判据命中率** = 组内**满足的判据要点数 / 判据要点总数**（组内统计口径，**不用于单条判定**）。低于 80% 说明对应 reference 缺少可执行判据。
